结论速览

Executive Summary
  • 触发位置：检查审核是 chat 模式专属的一级路由分支。每条用户输入先经文本模型分类器（router.py:21）判定为 generate / check / chat，仅当明确判为 check 时才触发检查管线。
  • 触发方式：它不是 LLM function calling 工具，也不是 Skill——是 MainAgent.chat() 里硬编码在对话循环之前的分支（main_agent.py:155-165），触发后不进入对话历史。
  • 内部机制：check 内部采用两级分类——视觉模型"看图说话"生成图片结构化描述 → 文本模型据描述与用户意图二级分类，产出检查项清单和素材路径。
  • 硬性门槛：必须配置视觉模型（VISION_MODEL_* 三件套），否则 check 直接拒绝执行，无降级路径。
  • 不触发的路径：run 子命令（单次生成模式）不经过任何路由，永远不会触发 check。

一级路由：check 分支的触发条件

Level-1 Router

核心文件flowchart_agent/router.py（全文 49 行，单一函数 route_category()，router.py:21）

用文本模型做一次廉价的 JSON 分类（router.py:24-34），分类 prompt 在 prompts/route.py:3-13：

- generate：用户想生成、绘制、修改流程图/图表，或调整已有图的风格样式
- check：用户想检查、审核、检视已有的文档或图片——关注正确性、图与文字描述的
  一致性、敏感信息泄露等（如"检查这份文档"、"这张截图有没有问题"、
  "原理图和描述一致吗"、"帮我看看组网图对不对"）
- chat：以上都不是
容错策略"宁可不错分"：JSON 解析失败或类别不在 ("generate","check","chat") 时返回 None（router.py:35-46），调用方回退主 Agent 流程（router.py:3-4 注释）。分类结果只在 == "check" 时被消费，其余类别仅写日志（router.py:47）。

唯一调用点：main_agent.py:155-165（MainAgent.chat() 开头）

# 一级路由：check 类输入转交检查管线，不进入对话上下文
category = route_category(self._llm, user_input, has_images=bool(images))
if category == "check":
    if self._check_agent is None and self._output_root is not None:
        self._check_agent = CheckAgent(self._settings, self._output_root)
    if self._check_agent is not None:
        if self._on_progress:
            self._on_progress("已路由到文档检查，正在分析素材…")
        return self._check_agent.handle(
            user_input, images or [], on_progress=self._on_progress
        )
    logger.warning("[route] 无 output_root，check 分支回退主 Agent 流程")

Skill 机制与 check 的关系

Skills vs Check
check 管线不是 Skill，也不由 LLM function calling 触发——它是 MainAgent.chat() 里 function calling 循环之前的硬编码分支。主 Agent 的系统 prompt（main_agent.py:32-72）不含任何 check 指令，LLM 主循环根本不知道 check 的存在。

图 7 · check 分支与 Skill / function calling 的位置关系：分流发生在工具循环之前
  • 内置 Skill（flowchart_agent/skills/）：Skill 是最小 dataclass（base.py:10-31），build_skills()（builtin.py:169-545）注册 18 个基础工具 + 条件注册 run_command、ocr_image。其中没有任何 check/review 类工具。
  • 技能包 SkillPacks（顶层 skills/*.md + skillpacks.py）：提示词型插件，现有唯一插件 drawio-export.md，与 check 无关。
  • 生成侧的间接联系：create_diagram / modify_diagram 内部走 FlowchartAgent._verify（生成→渲染校验→视觉验证循环，builtin.py:296-301、399-401），属生成路径，并非 check 管线。

关键发现与文档漂移

Findings
  • 设计佐证docs/REQUIREMENTS.md:92-118 明确记载两级路由设计：一级分类（router.py）→ check 管线；"宁可不错分"回退策略（:96）；"看图说话 → 文本分类"技术路线与 CSV 报告（:99-117）。
  • 文档漂移docs/REQUIREMENTS.md:67 提到的 check/types.py 已改名为 items.py；README.md:101 仍写报告为 report.md，实际产物已是 report.csv。
  • 用户入口提示chat 帮助文本向用户披露了 check 入口示例：chat_cli.py:78-79（"检查 test_datas/check/... 里的流程图和操作步骤是否一致……产物在 output/check/"）。
  • 可扩展点新增检查项成本极低：加一个 prompts/check/items/<id>.py + 在 items.py 注册一行即可，无需改动路由与编排代码。
